# EXE Sandbox

A Windows-native executable sandbox with real-time monitoring and AI-powered log explanations. Launch any EXE in a contained environment and watch every file, registry, network, process, DLL, and memory operation as it happens — with plain English explanations generated by a fine-tuned T5 language model.

## Features

### Monitoring

- **File operations** — open, read, write, create, delete, rename
- **Registry access** — key creation, value modification, enumeration
- **Network connections** — TCP/UDP, DNS queries, data transfers
- **Process lifecycle** — creation, exit, child process spawning, threads
- **DLL loading** — library loads/unloads with path and size tracking
- **Memory usage** — allocation, free, protection changes

### Interface

- **Terminal** — syntax-highlighted, filterable, auto-scrolling
- **Process tree** — live parent-child hierarchy with 500ms refresh
- **Embedded window mode** — reparent the EXE's GUI into the sandbox via `SetParent`
- **Stats panel** — CPU, memory, threads, events, session duration
- **Drag-and-drop EXE loader** with command-line argument support

### AI-Powered Explanations

- **T5-small + LoRA model** — fine-tuned on 400K sandbox log pairs, runs locally on CUDA or CPU
- **KB mode** — click KB to enter focused analysis mode
- **Clickable log snapshot** — all terminal history presented as individually clickable lines
- **One-click explain** — click any line to get a plain English explanation in a side panel
- **UPDATE toggle** — freeze the snapshot to analyze a specific moment, or enable live tailing
- **Auto-retry** — if you click a line while the model is still loading, the explanation auto-runs when it finishes

### Knowledge Base

- **116 entries** across 14 categories explaining every event type, registry key, file path, network port, DLL, and memory operation
- **Searchable** — filter by keyword, category, or severity
- **Threat context** — security notes for registry keys, ports, and suspicious behaviors

## Quick Start

### Prerequisites

- Windows 10/11
- Python 3.10+
- pip
- NVIDIA GPU with CUDA (recommended, falls back to CPU)

### Installation

```bash
git clone https://github.com/Abyssal-LLM/EXE-sandbox-and-monitor-v2.git
cd exe-sandbox
pip install -r requirements.txt
```

### Run

```bash
python main.py
```

The first run will download the T5-small base model (~60MB) from HuggingFace and cache it locally. Subsequent runs load from cache.

---

## Usage

1. **Drag and drop** an `.exe` onto the loader area, or click to browse
2. Optionally add **command-line arguments** and a **working directory**
3. Toggle **EMBED WINDOW** to embed the EXE's GUI inside the sandbox
4. Click **START** to launch and begin monitoring
5. Watch events stream in the terminal — use the filter checkboxes to focus
6. Click **KB** to enter Knowledge Base mode — a snapshot of all logs appears
7. **Click any snapshot line** to get an AI explanation in the side panel
8. Toggle **UPDATE** on to live-tail new events, or leave it off to freeze the snapshot
9. Press **Escape** or click **X** to exit KB mode
10. **Export** logs to a `.txt` file for analysis

## Monitoring Details

| Category | What It Captures | Technique |
|----------|-----------------|-----------|
| **File** | Open, read, write, create, close, delete | `psutil.Process.open_files()` polling |
| **Registry** | Key create, open, set value, delete, enumerate | `winreg` hive scanning |
| **Network** | TCP/UDP connect, send, receive, close, DNS | `psutil.net_connections()` polling |
| **Process** | Create, exit, child spawn, thread create/exit | `psutil.process_iter()` + `psutil.Process.children()` |
| **DLL** | Load, unload with path and size | `psutil.Process.memory_maps()` polling |
| **Memory** | Alloc, free, protect (RSS/VMS delta) | `psutil.Process.memory_info()` polling |
| **Handles** | Handle count changes | `psutil.Process.num_handles()` |
| **Threads** | Thread count changes | `psutil.Process.threads()` |

## AI Model

The explanation engine uses a **T5-small** (60M parameter) base model fine-tuned with **LoRA** (Low-Rank Adaptation) for efficient inference.

### How it works

1. User clicks a log line in KB mode
2. The line is prefixed with `translate sandbox log to English: `
3. T5 generates a plain English explanation (~1-2s on GPU, ~5-10s on CPU)
4. Explanation appears in the side panel

### Configuration

- **Base model**: `t5-small` (downloaded from HuggingFace on first run)
- **Adapter**: `model/lora_adapter/` (bundled with the project)
- **LoRA config**: r=16, alpha=32, target_modules=["q", "v"]
- **Inference**: 4-beam search, max 128 tokens
- **Device**: Auto-detects CUDA, falls back to CPU

### Requirements

The AI model requires additional packages beyond the core sandbox:

| Package | Version | Purpose |
|---------|---------|---------|
| `torch` | >= 2.0.0 | PyTorch for model inference |
| `transformers` | >= 4.30.0 | HuggingFace T5 model |
| `peft` | >= 0.4.0 | LoRA adapter loading |
